# MEMORY.md

这份文件定义仓库的**长期记忆策略**：哪些历史该落盘、记成什么形态、谁来写、何时归档，避免 AI"记得住流水账却学不到判断"，也避免仓库变成每个会话都要读的大文件。
核心立场：**仓库是唯一事实来源**——如果 agent 不能在仓库里发现某个事实，就把这个事实视为运行上不存在（呼应 `design-docs/core-beliefs.md`）。

## 记忆分层（该记什么、记成什么）

| 层 | 内容 | 形态 | 谁更新 | 读法 |
|----|------|------|--------|------|
| ① 现状真相 | 当前架构/行为/计划/质量 | 既有治理文件（`ARCHITECTURE.md`、`product-specs/`、`exec-plans/`、`QUALITY_SCORE.md`） | 每次变更同步改写 | 开工必读 |
| ② 决策理由 | 为什么选 A 不选 B、trade-off | `design-docs/`（accepted/proposed） | 决策当下写一次 | 相关时下钻 |
| ③ 完成工作 | feature / 修复 / 调研 的历史 | `exec-plans/completed/` + 摘要入 `HISTORY.md` 索引 | 收尾时 | 按需检索 |
| ④ 经验与模式 | 反复踩的坑、review 反馈、领域知识 | 升级为规则/检查/新文档（勿留在对话里） | 出现第二次时 | 机械执行或短读 |
| ⑤ 原始流水 | 对话记录、实验细节、大块数据 | **不写正文**：只留结论 + 指针（`references/`、`generated/`、平台会话存储） | 尽量少 | 几乎不读 |

判断标准一句话：**只有"可复用判断"值得进仓库正文；发生过的事只留"一行摘要 + 链接"。**

## 历史索引（`docs/HISTORY.md`）

回答"这个模块最近改过什么、修过哪些问题"的唯一时间线入口。规则：

- 每行一条：`日期 | 类型 | 区域 | 一行摘要 | 详情链接`；类型 ∈ `feat / fix / research / rule / arch / chore`。
- **正文只放摘要行**，细节一律链接到 `completed/` 计划、ADR 或 spec——禁止把完整经过写进索引。
- 新行由 agent 收尾时追加（见下）；不列入 `AGENTS.md` 路由地图——它是**检索件，不是必读件**（必读集合收敛原则）。
- 漂移即技术债：摘要与链接文件对不上时，记入 `exec-plans/tech-debt-tracker.md`。

## 收尾纪律（衔接 `AGENTS.md` 收尾）

每次会话结束，变更必须归入且只归入三类之一，**禁止新增"第四处"重复描述**：

1. 改了现状 → 更新对应治理文件（①）
2. 做了一个决策 → 写/改 `design-docs/`（②）
3. 完成了有边界的任务 → 计划移 `completed/` + `HISTORY.md` 加一行摘要（③）
4. 出现了第二次的反馈/坑 → 升级为规则/lint/小文档（④），并留痕"从口头变成规则"

无相关变更可跳过；拿不准记不记时，按"未来一个没有聊天上下文的 agent 是否需要知道"判断。

## 记忆卫生

- **必读集合收敛**：每个会话固定必读的（AGENTS + 路由指向的治理文件 + active plan）保持 ~常数；新增内容一律走链接，禁止把历史细节写进必读文件正文。
- **检索优于预载**：历史只在相关时才下钻；默认不进上下文。
- **判断优先于流水**：值得存的是理由与规则，不是流水账；流水账摘要化后归档。
- **机器可查的不写成散文**：能用 lint/脚本/链接自检执行的，别让 LLM 每次读文字（机器查 ≈ 0 token）。
- **定期归档**：`HISTORY.md` 超过约 150 行时，把最旧一年段移入 `docs/generated/history-archive-YYYY.md`；`completed/` 只留"仍要参考上下文"的计划，其余摘要化后归档。
- **别过早开层**：小项目/会话数少时，直接沿用 completed plans 即可；`HISTORY.md` 在历史开始"翻不过来"时再启用（平衡点见下）。

## Token 经济学（为什么这套纪律省 token）

单会话成本 ≈ 启动必读 C₀ + 按需检索 R + 写入 W + 压缩纠错。纪律的作用：

- 把 **C₀** 压成恒定小（渐进披露，仓库变大不进上下文）
- 让 **R** 准且浅（索引命中 → 下钻 1 个文件，减少检索失败与来回）
- 让 **W** 有上限（一行摘要 / 一次 ADR / 一条规则）
- 减少 compaction 把流水垃圾喂回上下文

净收益有**平衡点**：会话数十次或历史"翻不过来"之前是投资期，之后净省。真正的成长 = 判断存量（ADR/规则）增加，而不是上下文载入量增加——固化"为什么"与规则，同类问题第二次不再重新分析（省的是最贵的试错/重试 token）。
