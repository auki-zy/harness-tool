# 权限档位参考（Permission Profiles）

> 工具中立的权限档位语义：把"agent 的审批强度"按任务类型切成几档，而不是每次会话都重新讨论"能不能跑这个命令"。
> 本文描述**档位语义**；具体工具落地方式不同：DSH 沙箱/审批策略、Claude Code 权限模式、Cursor 规则等按各自配置映射。

## 档位一览

| 档位 | 允许范围 | 典型用途 | 对应审批强度 |
|------|---------|---------|-------------|
| `read` | 只读：查看文件/文档/搜索 | 理解代码、回答疑问、review | 最松（无副作用即无审批） |
| `plan` | 只读 + 写文档/计划文件 | 开工调研、写 plan/spec/设计文档 | 低 |
| `edit` | 文件读写 + 本地构建/测试/格式化 | 正常开发：改代码、跑 typecheck/lint/test | 中（默认） |
| `approve` | 上述 + 需要显式确认的动作 | 安装依赖、改配置、网络请求、发布 | 高（每次确认） |
| `full` | 不受限 | 特殊情况（经评审） | 最高（默认禁止，逐次授权） |

## 选择规则

- 任务边界决定档位，不是凭感觉：只读分析用 `read`/`plan`，写代码用 `edit`，碰外部世界用 `approve`。
- 档位**只升不降要理由**：需要提升时，在 plan 里说明"为什么这步必须更高权限"。
- agent 无法自证需要高权限时，回退到低档 + 请求确认，而不是直接默认高档。

## 与 SECURITY.md 的关系

- `SECURITY.md` 定义"哪些动作必须显式批准 / 默认不能跑"；本文件定义"按任务切档"的工作方式——两者配套：本文是会话粒度，SECURITY 是动作粒度。
- 新项目 bootstrap 时选一个"默认档"（前端日常开发通常 `edit`），把高档位动作留成显式审批项。

## 机械执行建议

- 优先用工具自带的权限/沙箱配置表达档位（比让 agent 自觉遵守可靠）；
- 把"默认档 + 高危动作白名单"写进 `SECURITY.md` 与工具配置，两边保持一致。
